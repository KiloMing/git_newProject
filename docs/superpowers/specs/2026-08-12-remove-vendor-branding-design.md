# 全仓库代码品牌信息清理设计

## 目标

清理 `E:\git` 仓库全部代码文件中的正点原子相关品牌、作者、版权、公司与宣传网址信息，同时保持技术注释的含义、源文件编码、程序逻辑和运行行为不变。

## 处理范围

仅处理代码文件：

- C/C++ 源码与头文件：`.c`、`.h`、`.cpp`、`.hpp`、`.cc`、`.cxx`
- 汇编源码：`.s`、`.asm`

不处理以下内容：

- Markdown、TXT 等说明文档
- PDF、ZIP、Excel、图片及其他二进制资料
- Git 内部数据和编译输出目录

## 清理规则

从代码注释中移除：

- `正点原子`、`ALIENTEK` 及大小写变体
- `星翼电子`、公司名称与版权归属行
- 官网、论坛、教学视频、购买地址等宣传信息
- 指向上述主体的作者字段

具有技术含义的注释不得整体删除，必须改成中性描述。例如：

- “正点原子触摸驱动”改为“触摸屏驱动”
- “正点原子 LCD 驱动”改为“LCD BSP 驱动”
- “正点原子 H743 开发板”改为“STM32H743 开发板”

纯宣传、作者或版权行直接删除。注释分隔线和空行可适当收拢，但不得破坏注释语法。

## 行为保护

不得修改：

- 函数、变量、宏、枚举和类型名称
- 字符串常量中的运行时协议内容
- 寄存器、引脚、地址、时钟、阈值和通信参数
- Keil 工程配置、链接脚本和构建参数
- 文件名、目录名和 include 路径

处理前识别各文件原始编码，写回时保持原编码和换行风格，避免中文注释乱码或大面积无关差异。

## 验证

1. 对处理范围内的代码文件重新检索全部品牌关键词，结果应为零。
2. 检查 Git 差异，确认变化只发生在注释和空白行。
3. 使用 `git diff --check` 检查空白错误。
4. 完整编译仓库内可用的 H743 Keil 工程；当前主工程必须达到 `0 Error(s), 0 Warning(s)`。
5. 不自动提交或推送修改。
